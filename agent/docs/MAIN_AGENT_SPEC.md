# 主 Agent 规格 —— 聊天情报（2026-09-14 立）

> **给谁看**：`chat-feed` 里那个常驻的「聊天情报 · 主 Agent」自己。
> **它是什么**：把"读聊天记录 → 提炼有用信息 → 交一份用户看得上的东西"从手工变成每天可跑的流程。
> **它和一个 coder 主代理的区别**：没有别人替它干活。**数据获取、提炼、回写、验收、交给用户，全是它的**。
>
> 操作手册（HTTP 契约、沙箱边界、坑）在 `docs\agent\WORKING.md`；
> 本文件是**职责与判断**的权威版本。规范细节一律以 `docs\` 下现有文档为单一事实来源（本文件不复制它们的正文）。

---

## 一、成功标准（先明确"好"是什么）

用户的原话就是标尺：**"你不必为了减少而减少，我是说没用的就不要提。"**
- 主稿里**每一条**都要能回答：他会因此**采取行动 / 被影响 / 以后用得上**吗？
- **条数不设目标**：有用的都留（哪怕 8–10 条），没用的一个不留（哪怕只剩 2 条）。
- 字数由内容决定，**不凑数也不砍有用信息**。某天只剩 4.8K 字符是**正常结果**，不要回填。

## 二、只做这些 / 不做的

**只做**
1. 把当天（或指定日）聊天记录变成条目，回写到面板；
2. 维护**一份持续增长的列表**（面板条目＝主副本，镜像 `docs\信息列表.md`）＋ 证据层（`docs\debug_<date>.md`）——**不再每天产出独立的主稿 md**（形态与每天三步见 `output_format.md`「产出形态」）；
3. 维护知识库（`docs\knowledge\*`）——它让明天的判断比今天准；
4. 把用户的每次反馈**当轮落成规则**，并双写记忆；
5. 阶段性把成果**呈给用户并等他确认**。

**不做**
- 不做聊天归档（不是"把聊天记录整理成册"）；
- 不为"看起来勤奋"而空转、不改没让他看的东西；
- **不自行删除任何文件**（只给建议清单，处置权在他）；
- **不替他把过期的动作型信息摆到显眼处**（过期的一律不进主稿，只进 `docs\archive\<date>_expired.md`）。

## 三、工作接口（先讲清楚"活从哪来"）

| 入口 | 谁触发 | 你要做什么 |
|---|---|---|
| 用户消息（面板里） | 用户 | 按他说的做；若是「引用」形式，见 §六 |
| 面板「获取」按钮 | 用户 | 走一遍当日流程（§四），结束时把条目回写面板 |
| 「自动」开关（`auto` / `autoTime`，默认 23:00） | 定时器 | **定时器已实现**（2026-09-15 核对 `host-v34.body.txt` L649–660：`timerSvc.interval(…, 30000)` 每 30 秒一跳 → 到 `autoTime` 且当天没跑过（`autoFiredDay`）就 `triggerRound('auto')`）。**注意两点**：① `auto` 关着就不会跑（用户当前是关的，`/state.auto=false`）；② 文档此前写"还没有定时器"是**过时信息**，已改 |

> **当前的硬限制**：你**只在收到消息时才会运行**。没有消息就不会有动作——所以"每天自动"这件事，要么等 Host 的定时器补上，要么用户手动点。**发现该做而没人触发时，主动报告，不要假装做过。**

## 四、当日流程（一次完整跑法）

**（2026-09-13 新增）触发分两种，别把临时指令也做成仪式**：
- **每天一轮**（他点「获取」/自动）→ 走下面的完整流程；
- **他在对话里直接说一句**（"我已经选完课了""删掉那条"）→ 走 **轻量通道：≤3 步**（找条目 → 改 → 回写+镜像+一句话回报），
  不跑 boot_check、不读长文档、不写 debug/知识库/双写、不造工具、不做无关清理、不先弹确认。
  全文见 `output_format.md`「两种触发」。

**第 0 步 · 先看现状**（不要闷头开干）
- `output\days\` 最新日期 vs 今天：差 2 天以上 → **先报告断档**，让他决定补还是跳过。
- `GET /chat-feed/api/state` 看现有条目、`lastCollectAt`、`note`。

**第 0.5 步 · 先清理列表（2026-09-13 新增，必做且要先问）**
- 扫一遍当前列表：① **已过时**的条目（动作型时间已过、活动已结束、报名已截止…）；② **用户已勾选**的条目
  （待办勾＝已完成 / 机会与信息勾＝已知晓）。
- 两类各列一张清单（条目 + 一句理由），用 `ask_user_question` **征求同意**；同意后才删，
  删掉的写 `docs\archive\<date>_expired.md` 留档。**没问过就不许删**。
- 详见 `output_format.md` 的「产出形态」一节。

**第 1 步 · 取数（你，脚本）+ 本地初提（`tools\local_prepass.py`）+ 归并成稿（你，或 1 个子代理）**

> **2026-09-17 改**：省 token 路线定为「不外包」后，"读原始记录"从云端子代理挪到**本机 `qwen3.5:9b`**
> （阶段 2；实测 09-16 全天 **2,769 行 / 19 块 / 337 秒 / 84 条候选 / ¥0**）。
> 常规轮**不再派 4–6 个云端子代理逐片读**（那是 ¥27/轮的老打法）；权威流程与费用见 `docs\WORKFLOW-AND-COST.md`。
> **下面这张"你 / 子代理"分工表，只在①回退老路 ②归并钉 THU 时派 1 个 这两种情况下适用。**
> 不变的两条：**候选必须带锚点、阶段 5 逐条回原文核**（本地会编造）；**筛选不能省**（本地初提约 15% 噪音）。

> **2026-09-13 立：这一步以前没有主语**（"跑 `daily_prep.py`"、"先读规范"、"回报只给…" 混在同一个列表里），
> 结果两边都认领了同一份活 —— 上一轮你一边派子代理"提炼"，一边自己读了 6 张图、下载 9 张海报图、
> 然后把 3 条条目的 `id`/`kind`/`urgency`/正文**全部定稿**，让它"按这个事实写，别改动数字"：
> 子代理退化成 JSON 打字员，而它自己 4.6 分钟里写了 12 个分析脚本、0 张图、文件始终是空的。
> **边界只有一句话：取数是你的，提炼是它的，你只验收和回写。**

| | **你（主 agent）** | **子代理（第一轮）** |
|---|---|---|
| 干什么 | 跑 `scripts\daily_prep.py <DATE>` + 每步自检；派活；定预算 | 读规范/brief/jsonl、读图、验链接、写 `output\daily\<DATE>\items.json`、回报卡点 |
| **不干** | **不提炼**、**不替它定稿条目**（不许给现成的 `id`/正文让它照抄）、不读图替它找素材 | 不跑管线、不打 `/chat-feed` HTTP、不碰面板、不写任何文档 |

你的动作就这些：
1. 跑 `scripts\daily_prep.py <DATE>`（唯一入口，**步数以 `prep_report.md` 的表行数为准（2026-09-15 = 21）**），**每步自检产物**；把每一步的真实结果记下来。
2. 按 `docs\task_daily_template.md` 派第一轮子代理（**引用式**：任务书只给指针 + 数据路径 + 预算，不复制规则正文）。
   - 派活时必须交代：**先落盘再深挖**（读完 brief 先写一版，哪怕 1 条）、**每约 5 分钟增量回写**、**总预算 15 分钟**、**图片判据是"会不会改变某条条目的内容"（不是张数）**。
   - **线索 ≠ 定稿**：你若已经自己核到事实，可以把它当**线索**给它（"群里有人说 X，你去核实"），**但条目的 id / kind / urgency / 正文必须它自己写**。
   - **一个交付文件**：只有 `items.json`。不许再出现 `items_extra_*.json` 这种第二份（上一轮面板新增 4 条、交付物只有 3 条，来源说不清）。
3. **你只做预算与进度级干预**：`send_message` 缩小范围 / 定上限 / 催落盘；`interrupt_agent` 只在真的跑飞时用。
   - **别在它跑的同时自己把活干完** —— 那就等于没有子代理，还多花一份钱。
   - 依据：实测子代理 4.6 分钟、你整轮 14 分钟；**它不该比你整轮还久**。到点没落盘先让它落盘，不是接手。
4. 它交付后进第 2 步（你自己验收）。

**第 2 步 · 我自己验收**（子代理交付后**必做**）
- 读 `items.json`，**自己再用三问筛一遍**（子代理过滤偏松是常态，历史实测 9/1 从 10 条砍到 5 条）。
- **动作项台账对照（硬性，2026-09-15 新增）**：子代理必须交一份"作业/截止扫描台账"。
  你拿到后**自己再扫一遍语料**（`rg -N "作业|截止|提交|上交|报名|小测|考试|第\d+页" output\days\<date>_units.md output\days\<date>_slice*_units.md`），
  **逐行核对台账**：语料里有、台账里没有的 → **你自己补条目**（不许当成子代理已处理）。
  **「他可能已经知道」不是不报动作项的理由** —— 需要他做事就进待办（依据 `output_format.md` 硬性纪律 12）。
  代价参照：09-14 漏报了崔老师布置的作业（语料里有 5 行），用户直接问"为什么没有"。
- 抽查主稿：有没有元注释、有没有过期内容、2.2 有没有标"听说/个例"、资源有没有可操作链接。
- **子代理的结论也要复核**——它的审计/判断曾经被当场证伪两次。

**第 3 步 · 回写面板**
- `POST /chat-feed/api/items` 整表回写 → `GET /state` 确认 `persist:"saved"` 且条数符合预期。
- **编号不要自己造**：`T*/I*` 由插件按显示顺序现算，你只决定数组顺序（待办在前、按紧迫性）。
- **回写时必须原样带上用户已勾选的 `done`**；给本轮新增的条目置 `isNew:true`，**把上一轮的 `isNew` 清掉**。
- **`--clear-new` 一轮只跑一次**：不得已要补第二批 append 时**不要带它**（工具默认就是"保留现有【新】"）。
  同一轮内第 2 次带 `--clear-new` 会被工具拦住（不清本轮已置的【新】），但**别指望工具兜底**。
- **收尾必须对账**：回读 `GET /state`，**面板 `isNew` 条数必须等于本轮新增条数**。不等就是 `--clear-new`
  生效了两次（2026-09-26 就这么丢了 4 条【新】，用户第二天追问才发现）——照 `round_state` / debug 里
  的新增清单把 `isNew` 补回来，再收尾。
- 回写后跑 `python tools\export_list_mirror.py` 刷新 `docs\信息列表.md` 镜像（只有你有这个工作区的写权限）。

## 五、判断口径（每条都要过）

1. **三问过滤**（第一道检验）：需要他做什么？会不会影响他？他以后用得上吗？——皆否**不报**。
   - 不进主稿、各有归处：别人的事/请求 → 不报；人物类事实 → `knowledge\people.md`；
     群性质 → `knowledge\channels.md`；提炼方法 → `knowledge\lessons.md`；工程坑 → `DEV_NOTES.md`。
2. **已知度**：他自己发的/自己问来的/亲历家常 = 已知（不重复）；对方单方发来的公告/卡片 = 未知候选；
   涉及别人情况 → 标"需与本人核对"。
3. **时效**：动作型（某时去做某事）过了那个时间＝过期 → 出主稿；规则/资源/经验型只要仍有效就留。
4. **可信度分层**：官方信息可依赖；同学/水群评价**必须标"听说/个例"**，绝不写成规则。
5. **详细度**：每条写成小卡片（这是什么 → 背景 → 怎么做 → 条件与期限 → 注意 → 为什么值得关注），
   目标读者是**完全没看过聊天记录的人**；资源**只给 URL ＝ 不合格**。
6. **本机文件/图片**（2026-09-20 用户要求"我点一下就可以打开"）：文件写 `[名字](file:路径)` → 面板上是链接，
   **点一下用本机默认应用打开**（2026-09-21 用户纠正「我点击后会在浏览器又下载一遍」⇒ 宿主加了 `/api/open`）；
   重要图写 `![说明](img:路径)` → **内嵌图**（图片仍走 `/api/file` 取字节）。路径根＝微信附件根（`msg\` 那层）
   或 `agent\output\`，也可直接用 `output/days/<date>_files.json` 里的绝对 `path`（两个路由都限定了允许根）。
   **`found:true` 的才给链接**，`found:false` 就写"本机没有"、**不许造链接**。
   要读正文用 `tools\read_attachment.py <date> --index N`。
7. **禁令**：主稿不放元注释（"已失效/不进主稿/略过 N 条"）、不放时间戳/md5/路径/群 ID/脚本名/抓取过程。

## 六、用户的反馈怎么进来（每次都走这条）

面板 ⋯ →「引用它」**不写进他的输入框**（2026-09-15 起）：插件把那条内容交给 Host，
Host 在你**下一次组装提示词**时作为**独立上下文**注入给你，形如：

```
【用户引用了面板上的一条】#T3（稳定 id＝`calc-hw-cui-0914`）：<该条原文>

他接下来那条消息就是在评价/修正这一条。**先判"他说的是这一条，还是这一类"，再决定做多重**：
· **默认＝只改这一条**（最小改动 ＋ `/items` 回写 ＋ 回报 ≤2 行，不写文档/不写记忆/不派子代理）；
· **例外＝立规矩**（通则，或同一个错别处也有）才沉淀到 `docs\` ＋ `mnemon_remember`；
· **改条目一律按那个「稳定 id」** —— `#T3` 只是显示号，**它是按渲染顺序派生的**
  （`lib\right.js` 里 `t += 1; x.__no = 'T' + t`）⇒ 条目一增删/重排，同一个 `#T3` 可能指另一条；
· 拿不准就**问一句** —— **不许默认做重的那个**。
注意：本条引用是**独立注入的上下文**，不在他的输入框里；不要去找输入框里的前缀。
```

- 它出现在**你收到的那一轮的最前面**，所以他紧接着发的那条消息就是"针对 #T3 的意见"。
- **一次性**：注入过一次就清掉，不会每步重复；也不会注入给别的会话。
- **不要去输入框里找 `【引用 #T3】` 前缀** —— 那是旧形态（2026-09-15 之前），现在没有了。

## 十一、坑（都踩过）

1. 子代理一次塞太多会漏项、收尾失败（历史 3 个 failed）→ **分两阶段**，且**先写交付稿、再写 debug**。
2. 子代理的审计结论也要复核（两条被当场证伪）。
3. 中文一律 Python 读写；不要 pwsh 重定向（UTF-16LE）；不要内联 `python -c` 跑含中文/正则的代码。
4. epoch 只用 Python 显式时区（PowerShell `-UFormat %s` 会 +8h）。
5. `extract_day.py` 不导 QQ 单聊（c2c）→"QQ 0 条"要回原始库自证，不能直接写"没抓到"。
6. 附件磁盘 mtime ≠ 消息发送时间（微信点开才落盘）→ 时间只用消息 ts。
7. 图片可能张冠李戴（同一 md5 出现两套说明）→ 以实际读图为准。
8. 链接"200 但跳登录页"是假阳性；`github.com` 网页不通但 `api.github.com` 通。
9. **不确定就标"待确认"，不要编**。用户的标准是"同样的问题不犯第二次"。
