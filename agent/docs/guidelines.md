# 聊天记录提炼原则（用户口述，2026-09-11，持续追加中）

> 本文件记录用户对"聊天记录 → 提炼/归纳"工作的明确要求。只读文档，按用户口述追加；**落实前不写入记忆系统**。

## 原则 1：宁缺毋滥，但保留有用信息（不盲目拼接、不猜想）
- 只写有证据支持的内容；拿不准的删掉，不硬凑。
- **用上下文识别信息关联**：
  - 上下文推断**属于同一话题的连续信息，就要连在一起**（连成完整信息，不能因"跨消息"而拆开）
  - 同时**识别话题边界**：相邻但**不同话题**的信息不得绑定（不能因字面相邻就拼成一件事）
- 判断标准＝话题与语境，而非消息的字面相邻。
- 反例（已修正认知）："乔林避雷"（Mr.Fish）与"乔老师的书还没出版，但课程信息里已经写出来了"（影空.Y 转发卡片）——**是同话题的连续信息，应连在一起**（乔林教材相关提醒）；但两者都发生在**二手书交易语境**中，与王元庆求购的《现代生物学导论》**不是同一话题**，不得把"乔林"与"现代生物学导论"绑定。
- 正确表述示例："二手群里有人提醒'乔林避雷'（乔老师的书还没出版但课程信息里已列出）"——保留完整关联，但不声称乔林与现代生物学导论的关系。

## 原则 2：归纳要完整可懂，不能太简短
- 每条信息要让人**看得懂**：保留"谁、在什么情境下、说了什么、为什么/怎么知道的"。
- 太简短的碎片化表述（脱离语境的一句话）不合格。

## 原则 3：图片 / 文章 / 文件 → 都要读取内容并纳入归纳，不脑补（2026-09-12 更新）
- **图片**：现已具备读图能力（当前模型支持图像输入），`read_image` 可直接读取 `output\window\images\` 中解密后的 jpg/png/webp/gif（`wxgf` 动效图除外，需转码）。流程：图片消息 → 按内容 md5 定位本地解密文件 → **读取并如实描述图中实际内容**（文字/书单/图表/聊天截图等）→ 纳入所在话题的归纳。
- **文件（用户 2026-09-12 补充要求：不只看图和文章，也要顺便把文件看一看）**：消息里的文件附件（doc/docx/pdf/xlsx/zip/mp3/mp4…）微信已落盘为**明文原件**，路径 `attach\<会话md5>\YYYY-MM\Rec\<消息id>\F\0\<原文件名>`。要读取/提取内容后纳入归纳：文本与 Office 类提取正文；PDF 提取文字；音视频标注时长与可辨识信息，读不了就如实说明"未读取"。保留定位信息（会话+时间+发送者+原文件名）。
- **文章链接**：见原则 7（必须读正文再总结，不能只留标题）。
- 仍然禁止：描述内容里不存在的信息、凭印象猜测；定位不到文件或读取失败时，如实标注并给出定位信息（会话+时间+md5/文件名）。
- 案例（乔林案破案，2026-09-12 读取）：`<群名>\d78f93859e940f151ad1440e41a3a579.jpg`（1159×664）实为**教材书单截图**，8 行：「参透Python 乔林／微积分原理 崔建莲／英语议论文读写教程 刘梅华／经济学原理 曼昆／环境保护与可持续发展第二版 钱易,唐孝炎／可持续发展引论第二版 叶文虎／可持续发展论 张坤民／科技写作与文献检索 孙平,伊雪峰」→ 坐实"乔林避雷"针对书单首本《参透Python》的作者乔林；该图正是 10:36:52 天空卡片《有无出这些书的，可以联系我》所引用的图。

## 原则 4：语境跨会话，话题要串联
- 话不能脱离语境。用户可能先与某人私聊、随后又在群里发消息——**同一话题跨多个会话时，各处的相关信息都要注意并串联**，归纳按"话题"组织，而不是按会话割裂。
- 判断依据仍是话题与语境（同原则 1），只是范围不限于单个会话内部。

## 原则 5：去已知，不反复提
- 总结/呈现时，先比对"已知信息"（可能来自之前看过的聊天记录、记忆库、用户自己的了解），**已经知道的不重复列举**；重点输出：新的、变化的、需要行动的、需要核对的。
- **注意粒度**：「已知」是**按要点**判的，不是按整条消息判的 —— 详见**原则 6** 最后一条（他看过这条消息 ≠ 他知道里面的每个要点）。
- 例："9/14（周一）13:00 补退选抢课"——用户自己都记不清，就不算"已知"；反之用户明确知道的事（见原则 8 案例）不再提。
- **动作类不受「去已知」约束（2026-09-15 用户纠正，硬性）**：凡是要他**本人做一次动作**的
  （作业、交材料、报名、截止、回复、去现场），**不许以"他已经知道 / 看过"为由删掉** ——
  「已知」只作用于**信息类**，对动作类是**无效否决**。实测事故：09-14 崔老师布置的作业
  （课本第 10 页 3、4、8）在语料里、且当天群里反复讨论，却被当成"日常、他可能已知"漏报，
  用户原话「**这种重要的待办就算我看过也应该列进列表里啊**」。详见 `output_format.md` 硬性纪律 12。

## 原则 6：判断"用户知道哪些 / 不知道哪些"（已知度过滤器）
- 信号与倾向：
  - 用户**自己发送**的消息 → 大概率已知（但若内容是转述/替别人问，则"转述的内容本身"仍可能是新信息，按具体情况判断）
  - 用户**主动提问**得到的答复（如"可找老师手选（邮件）；形策可冲突同选、可先 2 后 1"是用户自己去问来的）→ 已知
  - 对方**单方面发来**的公告/转发/卡片（公众号文章、群通知等）→ 大概率未知，重点候选
  - 涉及**别人情况、需与用户本人对照**的 → 不能当作用户已知（例："日语/Python/思修/体育未中、仅写沟通选"是**小李**的选课结果，是否与用户一致未知 → 表述为"小李在群里的情况，若与您一致请核对"）
- 输出策略：**拿不准的一律标注"可能已知/请核对"**，不与"新信息"混排；真正的目的是筛出"用户不知道且对其有用"的信息。
- **「已知」是按要点的，不是按整条的（2026-09-13 用户纠正，重要）**：
  他看过 / 自己发过这条消息，只说明**他见过这条消息**，**不说明他把里面的每个要点都知道了**。
  - **判据**：把这条消息拆成要点 —— 日期 / 地点 / 条件 / 额度 / 办理入口 / **联系人·找谁办·谁能批** / 注意事项 / 技术口径 ——
    **逐点问"他知道这一点吗"**。只要有一个要点是**他不知道且用得上**的，这条就**不能整条丢掉**。
  - **正确处理＝降级不丢弃**：已知部分压成**一句背景**（"你之前问过 X"），**把未见的要点作为正文主体**。
  - **实测（这条规则的由来）**：09-13 的「清华专属算力券」被以"他自己问来的＝已知"**整条砍出面板**，只留了一句
    "可以在技术支持群里要求提额"，连**两位能批额度的对接人**（群里 `Maas平台支持工程师`、`并行AI云工程师3`）都没留下 ——
    而用户原话是"**虽然这个确实是我看过的，但他中间的信息我未必看全了，比如联系人我就没看**"。
  - 只有「**三问全否 且 每个要点都已知**」才整条不进列表；**拿不准一律按"未见过"处理**（宁可多一条）。
  - **动作项例外（硬性，2026-09-15）**：只要三问第 ① 问成立（要他做事），**已知度不起否决作用** ——
    该进待办就进待办，已知部分压成一句背景即可（见原则 5 末条与 `output_format.md` 硬性纪律 12）。

## 原则 7：公众号/文章消息 → 读正文再总结
- 消息是微信公众号/文章卡片（或链接）时，**读取文章正文**后再提炼，不能只留标题。
- 提炼重点是**行动要点**：可申领/可参与什么、怎么申领（入口/步骤）、截止时间、适用对象。
- 例：清华专属算力券 2.0（3000 万算力礼包，全体师生可申领，并行科技）；智谱 Coding Plan 这次没随券发——需要读文章确认申领入口与条件，不能只写"有篇文章讲算力券"。
- **实现（2026-09-12 已落地，纯后台零插件）**：`node scripts\fetch_article.mjs "<url>" "output\window\articles\<名>.md"` —— 本机直连（Node fetch + 浏览器 UA），提取标题/公众号/发布时间/正文，可后台批量跑。**不要用云端抓取工具**（`web_fetch` 走云端 IP，访问 mp.weixin.qq.com 会被反爬以"环境异常"拦截），也**不要依赖浏览器插件**（用户明确要求：不依赖其他插件，后台解决）。
- 元数据取法：标题 `<h1 id="activity-name">` 或 `var msg_title` 或 `og:title`；时间 `var ct`（Unix 秒）或 `id="publish_time"`；正文 `id="js_content"` 段，先剥 `<script>/<style>`。

## 原则 8：亲历/家常类信息 → 视为已知，不重复
- 家人动态、用户亲历或参与聊过的家常（例：妈妈在家人群晒结训照片、奶奶高兴、冯家人关注结训直播；老师近况——何莲摔跤腰伤巨忙、杜红梅带饭又瘦了、贝妮考年级 26；同学近况——张彧铭大一秋 26 学分/程设免修做科研/上学期学过日语二外 4 学分不轻松、严家乐周末答辩周六出发/可能参加 6 人篮球局）→ 用户自己知道，**不重复呈现**（除非其中隐含需要用户行动的提示）。

## 原则 9（助手工作原则）：先检索记忆，不凭印象下结论
- 凡涉及项目、历史决策、以往结论、"以前做过的事"，或需要判断"某事是否已知／是否做过"，**回答前必须先检索**：`mnemon_document_search` → 未命中再 `mnemon_recall`；检索不到才可以说"没有"。
- 运行时注入的记忆快照是**预算受限投影**，可能省略条目：**快照缺席 ≠ 不存在**，严禁据此断言"记忆里没有"；插件提示词本身已写明 "absence does not prove a historical fact"。
- 反面案例（2026-09-12）：仅凭当时快照断言"9/14 13:00 补退选"没被记忆保存 → 实际三层都有（热记忆 v10 条目 + 3 份文档 + Memory Spaces 4 条洞察）。
- 同理适用于工作区文件：先读文件/检索，再下结论；拿不准就说"我去查"。
- 已同步写入热记忆（MEMORY.md，importance=critical）。

## 原则 10：已过时的信息不再提（时效过滤）
- **判定核心＝"这条信息的作用时间过了没有"**。作用是"提醒现在去做什么"的即时通知，一旦其时间点过去，就不再作为行动项/提醒呈现。
- 用户举的反例：`【班委竞选】提前准备 3 分钟演讲 — 秀钟63family·辅导员陈龙涛 09:20` —— 这是即时通知，时间过了就不必再说。
- **可保留的例外**（并非一刀切删除）：
  - ① 产生**长期影响或状态变化**的事（如"某人已成为新群主""被拉进班委群"这类状态更新）；
  - ② **长期有效的规则/要求**（如"竞选演讲限 3 分钟"——若竞选仍开放则依然有效）；
  - ③ 用户明确要求回溯的内容。
- 判定不了就标注"时效：已过 / 待确认"，不要擅自删也不要擅自留。

## 原则 11：两种产出模式 ——「实时」与「总结」
用户明确的架构（2026-09-12）：
- **实时（用户预告，暂不实现）**：把**最有价值、最需要立刻解决**的事情用弹窗之类形式即时提醒。要求：只挑"紧急性高 **且尚未过期**"的（如"今天 13:00 大家茶、要穿秀钟文化衫"）；宁少勿多；过期即撤。
- **总结（当前在做）**：一天结束后跑，复盘**有用的信息**。要求：按原则 10 过滤掉已过时项；保留长期有效、状态变化、决策依据、值得留档的内容；按价值排序。
- 两者共用原则 1–9，差异在**时效过滤强度**与**呈现颗粒度**：实时＝少而急；总结＝全而有据（但剔除已失效的提醒）。

## 原则 12：积累"经验知识"，越提炼越聪明（用户 2026-09-12 明确）
除聊天里的**事实信息**外，还要记住**从聊天记录中获得的经验知识**，用于提高下一次提炼的判断力：
1. **人物档案**：谁是谁（身份/关系/角色/称呼）、在哪些会话中出现、其消息通常的价值与说话特点（谁是辅导员、谁是家人、谁的发言常带行动项）。
2. **用户本人的表达风格**：用词、语气、标点与表情习惯、常见句式——用于准确识别"哪些是用户自己发的"、理解真实意图（直接服务原则 6 的已知度判断）。
3. **会话/群档案**：每个会话/群的性质与价值（官方通知群 / 班级群 / 课程群 / 二手交易群 / 宿舍楼群 / 兴趣群 / 家人群…），以及常见内容模式。
4. **提炼经验**：哪类信息有价值、哪类是噪音、常见话题模式、已经踩过的坑。
要求：
- **与事实总结分开存放**：经验库放 `docs\knowledge\`（`people.md` / `style.md` / `channels.md` / `lessons.md`）；事实总结仍按 `output_format.md`。
- **流程固定**：每次提炼**先读经验库**（提高判断力）→ 提炼 → **把新获得的经验写回经验库**（形成积累）。
- 经验条目**必须有证据**（来自哪些消息/统计数字），不确定的标"推断/待观察"，**禁止以偏概全**（一次发言不能定性一个人）；不写无助于提炼的隐私评判。

## 原则 13：资源型信息要挖到"可操作链接"（用户 2026-09-12 明确）
对"可领取 / 可报名 / 可下载 / 可使用"的资源型信息（如"智谱清言有活动可领一年会员"），**必须深挖到能直接点的程度**，链接获取按以下优先级：
1. **上下文里已提到链接 → 最好**：直接用，并**验证可访问性**（状态码 + 页面标题 + 是否需登录/已失效）。
2. **上下文没提链接 → 上网搜索官方入口**：优先官方域名/官方发布；不拿不明中转站、聚合页充数。

附加要求：

## 原则 15：图片选择性阅读（对原则 3 的效率补充，用户 2026-09-12）

## 原则 24：自进化的边界 —— 只产出「你能验证」的改进项（2026-09-14 用户纠正）

## 原则 25：**成本纪律 —— "给模型看的"与"给人看的"分开**（2026-09-15 成本审计后立）

> 依据：`D:\Project\DSH\docs\TOKEN-COST-AUDIT.md`（763 个会话，适配器上报的真实 usage）。
> 结论先说：**子代理占全部 token 约 96%，主 agent 只占 4%** —— 但主 agent 是"成本开关"（派几个、给什么上下文全在它手里）。

1. **大产物是"索引"，不是"读物"**：`_timeline.md`（~813 KB）、`_units.md`（~400 KB）一律**只读开头那段**
   （timeline 的「跨群线索索引 A/B」、units 的会话行数表），要细节就 `grep -n` 定位后只读片段。
