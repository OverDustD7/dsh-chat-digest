# 每日任务书模板（v2 · **引用式**）

> 用法：复制本模板 → 把 `<DATE>`、`<负责范围>`、`<now>` 替换成实际值 → 派子代理。
> **2026-09-17 起**：本模板只在**回退老路**（本地模型不可用／一次补好几天漏）时用；
> 常规轮走 `docs\WORKFLOW-AND-COST.md` 的六阶段（本地 `tools\local_prepass.py` 初提 → 阶段 5 一次归并成稿 → 验收回写）。
> **规范不在本文件重复**（单一事实来源，避免多处不一致）：**原则**见 `docs\guidelines.md`；**格式**见 `docs\output_format.md`；**偏好**见 `docs\knowledge\preferences.md`；**人物/群/说话方式**见 `docs\knowledge\{people,channels,style}.md`。

---

## 0. 你的角色
独立完成 **`<DATE>`** 一天的**提炼**：读规范 → 读数据 → **产出 `items.json`** → 回报卡点与待确认候选。
> **产出形态（2026-09-13 变更）**：不再写每日 md —— 产出**列表条目**，全文口径见 `docs\output_format.md`「产出形态」。

## 0bis. 边界与预算（2026-09-13 立；上一轮两边都干同一件事，这节就是为了不再发生）
**谁干什么**（主 agent 与子代理的边界，主 agent 那侧同口径见 `MAIN_AGENT_SPEC.md` §四）：

| | 主 agent | **你（第一轮子代理）** |
|---|---|---|
| 取数 | 跑 `scripts\daily_prep.py <DATE>` | **不跑**，直接用产物（除非任务书明确让你跑） |
| 提炼 | **不提炼**、**不替你定稿条目** | **全部归你**：读 brief/jsonl、读图、验链接、写 `items.json` |
| 回写面板 | `/items` 整表 + 镜像 | **不打任何 `/chat-feed` HTTP、不碰面板** |
| 收尾 | 知识库 + 双写 + debug + 呈交 + 问用户 | **不写任何文档**（连 debug 都不写） |

**三条硬纪律**：
1. **先落盘再深挖**：读完规范与 brief **立刻**写一版 `items.json`（哪怕只有 1 条、正文先短），再回头补图 / 补链接 / 加详细度。
   *依据*：2026-09-13 那一轮的子代理在 4.6 分钟里写了 **12 个临时分析脚本**、**0 张图**没读、文件始终是空的，最后被掐线重下指令。
2. **增量回写**：此后**每约 5 分钟**把新发现合并进文件一次，不要攒到最后一次性写完。
3. **总预算 15 分钟**：锚点是"主 agent 整轮（取数 + 派活 + 验收 + 回写 + 收尾）实测 14 分钟"——**子代理不该比主 agent 整轮还久**。
   到点无论深浅都定稿回报，把没做完的写进"没做到/没读到"。

**图片怎么算够**：判据是「**这张图会不会改变某条条目的内容**」（有没有日期 / 条件 / 链接 / 名单 / 二维码），
**不是张数**（用户口径：有用的都留、没用的一个不留 —— 硬性张数上限会正好砍掉那张写着截止日的海报）。
排序照下面第 3 节的说明。表情包 / 梗图 / 随手拍跳过，**在回报里写数量**。

> **不许出现第二个交付文件**：只有 `output\daily\<DATE>\items.json` 一个。上一轮主 agent 另外写了 `items_extra_*.json`，
> 结果"面板新增 4 条、第一轮交付物只有 3 条"，来源说不清。

## 2bis. 提炼前要看的三份视图（2026-09-13 加；**2026-09-15 改读法**）
> **为什么要改读法（成本审计实测）**：`_timeline.md` 有 **813 KB**，整读一次就是几十万 token；
> 而"每片派一个子代理"会让**每个子代理都整读一遍** → 实测提取类子代理每步 **34.7 万 token、缓存读 340 亿**，全场最高。
> ⇒ 「要看什么」不等于「要整份读进上下文」：**主 agent 只读摘要头 + grep 定位；子代理只看自己那一片。**
1. **`output\days\<DATE>_timeline.md`（跨会话时间轴）** —— 它是**检索用的索引**，不是阅读材料：
   **只读它开头那一段**：标题与「保留 N 行 / 丢弃 M 行」+ **「跨群线索索引（先看这里）」的 A/B 两节**
   （A＝同一段文字出现在多个会话＝同一份通知被多群转发；B＝同一链接/域名出现在多个会话）。
   要具体线索时 `grep -n "<关键词>" output\days\<DATE>_timeline.md` **定位后只读那几行**；**子代理不读它**。
   为什么不能省掉这层判断：同一件事的碎片会落在不同会话、隔着几十行 ——
   实测 `舞会 10/11` 散在 3 个会话（秀钟6交流群 01:28 / 尤勇 10:09 / 秀钟63family 11:05），**分组读串不起来**。
2. **`output\days\<DATE>_articles.md`（文章卡片清单）** —— **凡是"本地有正文"的，必须把正文读完再写条目**；
   本地没有的才考虑 `node scripts\fetch_article.mjs`（现在常被反爬拦到 captcha → 抓不到就**如实标注**，不要静默跳过）。
   实测：算力券那条只读了群消息，漏了文章里的线下联系人「<联系人> <电话> / 华业大厦 1103」。
   **本地正文缓存目录 = `output\window\articles\`**（历史上抓过的都在这里，先查它再考虑联网）。
3. `output\days\<DATE>_brief.md` —— 按会话分组的简报（用它定位细节，不要只靠它建立全局）。
4. **`output\days\<DATE>_threads.md`（主题跨天回溯）** —— 今天出现的**文章URL / 卡片标题 / 域名**里，
   哪些**前几天也出现过**。看到"以前也出现过"，就去核对**这是不是同一件事的第 N 天、口径有没有变**（原则 17：
   下集的价值点常常是口径变化，不是事件本身）。实测：算力券那篇文章 09-12 与 09-13 各被转发过一次，两天各写各的、
   没人告诉你是"第 2 天出现"。

### 2bis-2. 省 token 的固定四条（2026-09-15 成本审计后加，**写进每一份任务书**）
1. **只读指定输入**，读完**立刻落盘第一版**（哪怕只有 1 条、正文先短）；
2. 此后**每约 5 分钟增量回写**；
3. **禁止把原文贴回对话** —— 对话里只写结论与新发现；
4. **总预算 15 分钟、步数上限 ≤80**：到线先落盘再停；没做完的如实写进"没做到/没读到"。
外加两条同级的：
- **派活前先确认"筛"已经做完**：子代理的输入必须是 **3i 之后**的产物（本地小模型已丢约七成噪声），
  别让"筛"变成可有可无的步骤；
- **大产物只给路径、不给内容**：超过 50 KB 的产物（`_timeline.md` / `_units.md`）一律"给路径 + 让它 grep"，
  **不许在任务书里贴正文、也不许要求它整读**。

## 2ter. **话题归并（必做，2026-09-13 立）** —— 这一步只有你能做，脚本做不了
**脚本只负责把材料摆到一屏**（时间轴把全会话按时间合并、索引标出跨群同文）。**"这是同一件事"这个判断必须由你来做。**
不做的后果：同一件事被写成几条零碎条目、或者干脆一条都不报（实测 09-13：「10/11 书院舞会」这条线索
散在 **3 个会话**里 —— 秀钟6交流群 01:27「舞会吗 / 六度连接·第一次舞培&正装团购」、
尤勇 10:09「你们要来那 / 我是说正式的舞会」、秀钟63family 11:05「@所有人 没填的同学抓紧啦（引用：尺码统计）」——
**根本没进列表**，只被当成"要不要报"的问题扔回给用户）。

> **反面教材（2026-09-13 晚实测，务必读）**：规范第一版举例时我把
> 「舞会 ＝ 舞培 ＝ 正装团购 ＝ **尺码统计**」写成了"同一件事的四个面"——**这是错的**。
> 回原文核实：09-12 17:30 同一个人在同一个群发的是「学院会给每位同学**定制帽衫**，请在今晚完成尺码填写」+
> 那张「尺码统计」小程序卡 → **尺码统计是班服/帽衫的尺码，跟正装团购无关**。
> 两条教训：① **归并最怕"看起来像"** —— 语义相近的信号只能提示你去怀疑，**必须回原文核实**才算合并；
> ② **举例不能把推断写成事实** —— 一个错的例子会教出一次错的归并，还会顺手掩盖一条真待办
> （帽衫尺码他 09-12 没填、09-13 还在被催，本来该是一条待办）。

**怎么做（通读时间轴之后、动笔写条目之前，先做一轮）**：
1. 扫一遍时间轴里**带 ★ 的行**（跨群同文）与**线索索引**，再扫**同一时段前后 1–2 小时**的行 ——
   同一件事在不同群、不同人嘴里往往**换词**（舞会 / 舞培 / 正装团购 是同一件事的三个面；
   注意**别把"看起来像的"并进来** —— 见上面「尺码统计」的反面教材）。
2. 合并信号（**任一命中就该怀疑是同一件事**，不要求全中）：
   - 同一天里**不同会话**出现，且**时间挨得近**（同一晚/同一小时）；
   - **连续几天**反复出现（配合 `_threads.md`）；
   - 出现**同一链接/同一卡片标题/同一活动名/同一批人**；
   - 一段对话里 A 说的事，B 在另一群问的正是它。
3. 合并后的条目：**把这件事的全貌写清**（是什么 → 涉及哪几方 → 他现在要做/以后要做什么 → 期限），
   而不是把碎片并排贴在一起。**发现同一件事已经有一条了，就改那一条，不要新开一条。**
4. 归并完再过一遍三问：**仍然"三问全否"的才不报**。别用"拿不准"当作不归并的借口 ——
   归并是你判断力最该用的地方（真拿不准的是**政策口径**，那才走「待确认价值」）。

## 3. 提炼要求
**先读**：`guidelines.md`（尤其原则 **5/6**（已知度按要点判）18/19/20/21（价值门槛、详细度、图片、文件））· `output_format.md`（「产出形态」「价值门槛」「硬性纪律」）· `knowledge/preferences.md`（**他的关注偏好**）· `knowledge/{people,channels,style}.md`。

**然后严格按 `output_format.md` 的「产出形态」+「分类与详细度口径」产出**（此处不重复；
每条＝一句话总结 + 小卡片正文，新条目 `isNew:true`）：
- 一、待办（按紧迫性 🔴 今天 / 🟡 本周 / ⚪ 更远）
- 二、机会与招募（⏳ 24 小时内 / 🟡 本周内 / ⚪ 更远 截止；`kind='chance'`）
- 三、有用信息（3.1 官方信息 / 3.2 同学与群里的经验 / 3.3 资源与工具 / 3.4 生活与办事）

- **公众号作者每天扫一遍（2026-09-15 用户要求：「你每天都该看一眼（别人转发的，自己在网上搜）」）**：
  读 `output\window\biz_authors.md`（管线步 **3k-b** 已自动生成）的「**值得关注但他还没关注**」候选池 ——
  里面是**别人转到群里/私聊的文章的作者**（微信只把**他已关注**号的推送写进本地，所以只看本地推送永远发现不了新号）。
  把**值得的**补进 `docs\knowledge\official_accounts.md` **第一节的对应分类**（**别新开"补录块"**，见 `EVOLUTION.md` §六），
  再自己 `web_search` 搜一遍清华/自动化/AI 方向的新号（**只收已证实存在的**；号名没把握就标"待确认"）。
  回报里写一行：本轮解出 N 个号、新增进档案 M 个。
- **动作项扫描 + 台账（硬性；2026-09-15 新增，起因是漏报了崔老师 09-14 布置的作业）**：

  **每一条都要有处置**：进了哪条待办，或写清为什么不进（例："是别人的课"）。台账写进你的交付回报（3–10 行即可）。
  **禁止静默丢弃**：语料里出现过、你的回报里查不到 → 算漏。
  同时记住：**"他可能已经知道 / 我看过"不是删除动作项的理由** —— 只要需要他做事就进待办（已知部分压成一句背景）。
  依据：`output_format.md` 硬性纪律 12 + `guidelines.md` 原则 5/6。
- **「水群/大群」别只按"有没有行动项"筛**（2026-09-13 用户纠正："这种本来就是看别人的评论的，你筛的太严就啥也看不到了"）：
  大群里**别人的经验、踩过的坑、对课/老师/平台/流程的集体评价、被反复问到的同类问题**都要收进 **2.2（同学与群里的经验）**，
  标"听说/个例"即可；该丢的是纯玩笑/玩梗/复读/无观点转发/与他会遇到的事无关的闲聊。**宁可多留一两条，也不要整群一条不出。**
  判据与做法见 `guidelines.md` 原则 18 里那条"水群/大群怎么筛"。

## 4. 知识库回写（**必做** —— 用户要求"不要让我反复提醒"）

## 8. 两阶段派活（2026-09-12 用户建议："分两次提 prompt，注意力会更好"）

**不要一次把所有要求塞给子代理**——一次给 10+ 条要求会稀释注意力，导致漏项与卡住（用户观察："流程中卡住的点比较多"）。**分两次发**：

### 第一轮（**提炼**；取数已由主 agent 跑完）
```
【第 1/2 轮】完成 <DATE> 的条目提炼（**数据不用你取**，主 agent 已跑 `daily_prep.py`）。
1) 冷启动卡：`agent\COLD-START.md`（**≤150 行，读完就能干活**）；
   需要哪条细节时**用 grep 定位片段**（如 `grep -n "硬性纪律" docs\output_format.md`），
```

### 2quater. 图片怎么读（本地视觉已预分诊，2026-09-14 接入）

- 每天管线会产出 `output/days/<date>_vision.md`（第 **3j** 步，本地 qwen3.5:9b 视觉，零 API 花费）。里面分三块：
  - **一、需强模型回看**：判出"有行动项 / 有关键字段 / 解析失败"的图 —— **这些必须自己看图**（别只看本地结论；
    本地结论只是提示，二维码/表格/海报的小字要自己确认）。
  - **二、判为无信息**：表情包/梗图/纯生活照/无信息截图（实测约占当天 49%）—— **不必再看这些图**，省的是最贵的 token。
  - **三、自证**：落盘图数 / 需回看数 / 判 noise 数 / 失败数 / 耗时。
- **fail-open 纪律**：本地判定解析失败或超时的图，一律并入"需回看"，**绝不允许当 noise 丢掉**。
- 每轮顺手**抽检 3–5 张判为 noise 的**（自己看一眼）—— 把"漏率"当指标，发现误判就把它挪进准则里。
- 注意：本地模型会读错小字/长表格；**只要图里有数字、日期、联系方式、二维码，就以你自己看图的结论为准**。

### 2quinquies. 拿到链接之后怎么读（2026-09-14 新增工具）
- **通用网页/云盘/官网**：`node scripts\fetch_page.mjs "<url>" [out.md] [--raw]`
  - 产物默认落 `output/window/pages/<host>_<slug>.md`；**判定字段会写清** `ok / http-<码> / needs-login / js-only / blocked`
    —— **只有 `ok` 才能引用其正文**；其余情况如实写"取不到/需登录"，**不许编造内容**。
  - **Seafile 分享链接**（`<站内链接>/d/<token>`）走专用分支：网页是 JS 壳（正文只有几个字符），
    但**免登录 API 可取到文件清单**（默认递归 3 层）。**坑**：同一 token 的 `/info` 返回 403、而 `/dirents` 返回 200
    —— **不要因为 info 403 就判"这条链不可用"**。
  - 取文件本体：`GET /api/v2.1/share-links/<token>/files/?p=<path>` 拿直链。
- **微信公众号文章正文**：仍用 `node scripts\fetch_article.mjs "<url>" "<out.md>"`（那个是微信专用）。
- **图片/海报**：先用第 3j 步的 `output/days/<date>_vision.md` 分诊，只对"需回看"那批自己看图。
