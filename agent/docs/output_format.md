# 聊天提炼 · 标准输出格式（v2，2026-09-12）

> **v2 核心变化（用户反馈）：分层输出。** 用户看的是**结论**，不是**证据**——"来源、证据这些一般都不需要"。
> 所有产出分两层，**不得混写**。

## 分层：主稿（给人看） vs 证据层（给审计/机器）

## 【2026-09-13 用户变更】产出形态：从"每天一份 md"改成"一份持续增长的列表"

> 用户原话："现在你不会像原来一样每天产出一个独立的 md，而是在 1、2 步的清理后，把新的信息直接缀在列表中，
> 并把新增信息加一个【新】的标识（记得把旧标识清理掉）。注意：你的信息详细程度要和原来文档中一模一样，
> 但你每一条信息可能有一个一句话总结放在最前面。"

## 两种触发：**每天一轮**（重） vs **临时指令**（轻，≤3 步）

| 触发 | 走什么 |
|---|---|
| 他点「获取」/ 自动获取 / 到点该做一天 | 完整流程：先清理（问过再删）→ 取数 + 提炼 → 自检 → 回写（含 isNew 记账）→ 收尾（知识库 + 双写 + debug）→ 关卡 |
| **他在对话里直接说一句**（"我已经选完课了""把那条删掉""这条改成…"） | **轻量通道**：① 看他这句话对应哪条（就在当前列表里找）；② 该删就删 / 该改就改，整表回写；③ 刷新镜像 + **一句话**回报。**≤3 步**。 |

**为什么**（用户 2026-09-13："流程太长了，为什么选课结束删除个日程都那么慢，磨磨唧唧的"）：实测一轮 15+ 步、
每步 8–20 秒模型延迟，其中真正"删一条"只占 2 步 —— 其余全是仪式。

**轻量通道明确不做**：
- 不跑 `python tools\boot_check.py`、不复读长文档（规则你已读过）；
- **不写** `debug_<date>.md`、**不回写知识库**、**不 `mnemon_remember` 双写**（需要记的攒到当天那轮，或他要求时再落）；
- **不为一个小动作造工具**：删/改条目用现成脚本或一次性 5 行 python（整表回写 + 回读自证）即可；
  真要产出一个可复用脚本，**先说一句**（上一轮为删 1 条现写了两个工具，把 3 分钟的事做成了仪式）；
- **不做无关的"顺手清理"**：只有"本次改动直接造成的残留"（例如刚删的那类在别处还有引用）才顺手修，**修完一句话告知**；
  规范的演进、别人的文档、历史遗留一律不碰；
- **不先弹确认**：他说的话就是指令，直接办；真歧义才问一句（并给可选项），别为一条删除先绕一圈；
- 删除留档只在 `docs\archive\<date>_expired.md` **追加一行**（条目 + 一句理由），不写整节。

**载体**：**面板列表**（插件条目）＝主副本；`docs\信息列表.md` 是它的自动导出镜像
（`python tools\export_list_mirror.py`）。**不再产出** `docs\summary_<date>.md`（历史那几份保留作对照）。

**每次「获取」（手动或自动）后三步**：

1. **过期清理**：把列表里（待办 + 有用信息）已过时的逐条列出 + 一句理由 → **征求用户同意** → 同意后删除，
   并把删掉的写进 `docs\archive\<date>_expired.md` 留档（用户看不到的位置）。
2. **已勾选清理**：用户在面板上勾掉的（**待办＝已完成 / 有用信息＝已知晓**，两类条目都有勾选框、逻辑一致）
   → 同样列清单 → **征求同意** → 删除并留档。
3. **追加**：清理完成后，把**新信息直接缀到列表上**（不新开文件）；新条目打 **【新】**、同时**把上一轮的【新】清掉**。
   每条＝**一句话总结**（第一行）+ 与原文档**一样详细**的小卡片正文（"详细度"标准见本文件下方，不变）。
4. **回写**：`POST /chat-feed/api/items` 整表替换 → 读 `/state` 确认 `persist:"saved"` 且条数符合预期
   → 跑 `python tools\export_list_mirror.py` 刷新镜像。

**条目字段**（`/items` 只认这些，多写的字段会被丢掉）：

| 字段 | 说明 |
|---|---|
| `id` | 稳定 slug（如 `en-exempt`）；**不要自己造 T*/I* 号**——编号由插件按显示顺序现算 |
| `text` | **一句话总结 + 空行 + 小卡片正文**；正文里的 `**加粗**`、http 链接、**本机文件链接/嵌图**都会在面板上照常渲染，换行保留 |
| `kind` | `todo` / `official`(2.1) / `peer`(2.2) / `resource`(2.3) / `life`(2.4) —— **没有"待确认"这一类**（见下） |
| `urgency` | `today` / `week` / `later`（只有待办用） |
| `done` | 用户勾选状态：**回写时必须原样保留**（那是他的操作，不是你的） |
| `src` / `date` | 来源渠道 / 该条来源日 |
| `isNew` | 【新】标识：本轮新增置 `true`，**下一轮清掉** |

> **`text` 的换行口径（2026-09-13 用户报"中间插了一堆空行，排版不一样"后写死）**：
> 面板 `.cfw-txt` 是 `white-space:pre-wrap` —— **正文里多写一个空行，屏幕上就真空一行**。

> **本机文件给可点链接、重要图给内嵌图（2026-09-20 用户要求："我点一下就可以打开"）**：
> - `[名字](file:路径)` → 面板渲染成链接，**点一下用本机默认应用打开**（docx→Word、pdf→PDF 阅读器…）。
>   2026-09-21 用户连纠两次：**"我点击后会在浏览器又下载一遍这个文件"**、**"最好所有文件都用本机默认应用打开吧"**
>   ⇒ 宿主因此加了 `POST /chat-feed/api/open`（内部走 `cmd /c start "" "<绝对路径>"`），点链接**不再让浏览器下载**。
> - `![说明](img:路径)` → 渲染成**内嵌图**（图片必须取字节，仍走 `GET /chat-feed/api/file`）。
> - 路径的根是**微信附件根**（`msg\` 那一层）或 **`agent\output\`**；也可以直接写
>   `output/days/<date>_files.json` 里那条的**绝对 `path`**。两个路由都**限定了允许根**
>   （拒绝 `..` 与根外绝对路径），写别处的路径点不开。
> - **什么时候给**：`found:true` 的才给链接（他点得开）；文件类消息**一律给链接**；
>   图片只有重要类（通知/名单/课表/截图）才嵌图，**不要每张都嵌**。
> - `found:false` 的写"本机没有" —— **不许造链接**（用户 2026-09-20："有一些文件被我移动了，那就是没有"）。
> - 要读文件正文：`..\venv\Scripts\python.exe tools\read_attachment.py <date> --index N`
>   （pdf/docx/xlsx/pptx/txt 可提正文；音视频**本线不转写**，只标未读）。
> 统一为「**一句话总结 + 恰好 1 个空行 + 正文（正文内部一律单换行）**」。
> **所有写入面板的通道都必须过 `tools\panel_fmt.py` 的 `normalize_text()`**（`panel_append_items.py` / `panel_patch_text.py` 已内置）。
> 实测：09-13 那条舞会条目正文内部用了双换行（双换行计数 8，其余条目全部是 1）→ 渲染出一堆空行。
>
> **`isNew` 的清理范围（2026-09-13 用户定案）**：**只有"当天那一轮"**才清上一轮的【新】；
> **轻量通道追加一条、以及"补做/回溯历史某天"这两种轮次都不清**。
> **判据＝【新】的语义是「他还没看过」** —— 清早了，他就失去了那条"这条是新的"提示。
> 落地：`panel_append_items.py` **默认不清**，要清必须显式 `--clear-new`。
> （踩过：一次轻量追加把当天已置的 5 条【新】全清，用户要求恢复。）
>
> **同一轮只清一次 ＋ 收尾必须对账（2026-09-27 定案，用户追问"本轮+5 怎么只有 1 条带新图标"）**：
> `--clear-new` 的语义是"清**上一轮**的【新】"，实现却是"**把现有条目的 `isNew` 一律置 false**"。
> 一轮里 append 两次（09-26 那轮就是：先写 4 条，后因 A79 又"换新 id 重写"1 条）且**两次都带** `--clear-new`
> ⇒ **第 2 次把第 1 次刚置的 4 条【新】一起清掉**，5 条新增最后只剩 1 条带【新】；
> 更糟的是**两批自检都打了"通过"** —— 各自只对自己那批算 `预期 = len(new)`，
> **单点自检一致 ≠ 全局账平**。
> 落地两条：① 工具记**轮次戳**（`output\window\.clear_new_stamp.json`），同一轮（3 小时内）的第 2 次
> `--clear-new` **不清本轮已置的【新】**，要全清得显式 `--force-clear-new`；
> ② **收尾必须核「面板 `isNew` 条数 == 本轮新增条数」**，不等就照 debug 里的新增清单补回来再收尾。
> ③ 不得已补第二批 append 时，**本来就不该带 `--clear-new`**（默认行为就是"保留现有【新】"）。
>
> **相对时间词禁令（2026-09-13 增量轮立）**：列表是**持续存在**的文档，条目里**不许出现「明天 / 今晚 / 今天 / 昨天 / 后天」**这类相对词
> ——隔天再读就读错（实测：`en-exempt` 写"明天 00:00 开放"、`industry-talk` 写"今晚就填"、`nextthuxk-220` 写"明天 13:00 前"，
> 09-14 一看全不对）。**一律写绝对日期**（`09-14 00:00`、`9/15 12:00`）；引述别人原话时若含相对词，要在括号里补出对应日期。



### 主稿 `docs\summary_<范围>.md`（默认产出，用户阅读）

> **详细度标准（2026-09-12 用户明确纠正，最高优先级）**
> - **形态按信息量定，不按模板套**（2026-09-20 用户纠正：*"你完全没必要每个条目都按照这个格式这么写，不能按情况来吗"*）：
>   **一句话能说清的就一句话**（例：「09-20（周日）微积分习题课在**四教 4106**；以后地点都写在习题课群群名里，看群名即可。」）；
>   **只有真有多要素时才展开**（入口 / 期限 / 条件 / 联系人 / 门槛 / 风险）——**没有的节一个都不写**。
> - **判据**：每多写一节，问一句"**这节多给了他什么他能用的信息**"；答不上来就删。
>   **反例**（2026-09-20 实测，245 字被压到 45 字）：一条"习题课地点"的条目写了「**这是什么**：助教 X 09-19 15:38 在群 Y 通知…／**怎么做**：按群名去／**为什么值得关注**：看群名就不会跑错楼」——**三节全是首句的复述**。
> - **仍然禁止"一行一条"的极简罗列**（用户原话："**你写这么短我也看不懂**""**提炼的太短了，我已经看不懂了**"）——那说的是**把该有的信息压没了**，不是**把没用的信息灌进去**。两者是两回事。
> - **资源/链接必须配详细说明**（名称 / 用途 / 怎么用 / 期限 / 奖励或门槛 / 注意点）；**只给一个 URL ＝ 不合格**。
> - **强过滤（少而精，不是多而全）**：① 用户**已经知道**的（他亲历的军训/团关系转接、他自己发的、他自己问来的、他本来就在用的工具）→ **一律不写**；② **已经过期**的 → 不写（原则 10）；③ 只写**他真不知道、且仍然有效/仍有影响**的内容。
> - 长度：交付稿 **6K–12K 字符**（**少而深**：一天 5–10 条高质量卡片，见原则 20；旧的 15–25K 与 ≤8K 均已废止）。

**价值门槛（2026-09-12 用户明确："价值低的东西就不用列出来了"、"太繁琐了…让人眼花缭乱，浪费时间"）**
一条内容要进主稿，**必须至少满足一条**：
- 能带来**实际机会 / 资源**（可报名、可领取、可下载、可用）
- 是**必须遵守的规则或风险**（会被执行、有后果）
- 是**影响你的状态变化**（谁到任、规则改了、名额变了、口径变了）
- 是**你确实不知道、且以后用得上的知识**
**不满足就删**——不许"降级保留"、不许"仅供参考"地凑数。

**⚠️ 第一道检验（2026-09-12 用户强化，优先级最高）：这跟我有什么关系？**
- 只写**与他本人有关**的：**他要用/要做的**、**会影响他的**（规则、状态变化、风险）、**他以后用得上的**（经验、避坑、资源）。
- **一律不写**：别人的请求、别人的成就、别人的社交、与他无关的活动。
  - 反例（用户点名）：**陈传奇请大家帮他 agent 聊三次打分** → 这是**别人的请求**，与他无关 → **删**。
  - 人物类事实（谁是谁、什么角色、常做什么）→ 属于**人物档案**，写进 `knowledge/people.md`，**不占每日报告**。
- 三问皆否就删：**① 需要他做什么？② 会不会影响他？③ 他以后用得上吗？**

**条数不设目标 —— 只看「有没有用」**（2026-09-12 用户澄清：「**你不必为了减少而减少哈，我是说没用的就不要提**」）：
- 判断标准只有一条：**这条对他有用吗？**（三问）
- **有用的都留**——哪怕当天 8 条、10 条；**没用的一个不留**——哪怕只剩 2 条。
- **禁止为了「看起来简洁」砍掉有用信息**；也禁止为了「信息量」塞没用的。
- **详细度不变**：小卡片照写，不要因为条数变化把内容压干。

**字数说明**：字数**完全由内容决定**，既没有下限，也没有必须凑到的数。若「仍然有用」的内容本来就少（例如某天 65% 都是过期信息），**短就是对的**——**禁止为凑字数放回过期或低价值内容**。
> 实例（2026-09-12）：9/2 原稿 11,465 字符，剔掉过期内容后只剩 **4,853**，低于 6K —— **这是正确结果**，不需要回填。

**分类与详细度口径（2026-09-12 定，**载体已改为列表**，见上节；下文"主稿"一律读作"列表条目"）**

1. **一、待办（需要你行动的，按紧迫性排序）** —— 只放需要他**本人采取行动**的事（报名、交材料、去现场、回复、取件），分三档：
   - **🔴 今天 / 24 小时内**
   - **🟡 本周内**
   - **⚪ 更远（长期 / 未来某天截止）**
   每条＝**做什么 + 时间 + 地点 + 要带什么**；已过期的删掉（历史日压成末尾一句话）。
2. **二、机会与招募（2026-09-13 用户要求新增；按"距截止的时间"分档）** —— 只放**可自由报名 / 可申请 / 可参与的机会**
   （岗位招新、比赛、大会、活动），与「待办」的分界＝**是不是他必须做的一次动作**：
   - **2.1 ⏳ 24 小时内截止** / **2.2 🟡 本周内截止** / **2.3 ⚪ 更远的截止或长期开放**
   - 每条＝**这是什么 + 谁办的 + 报名/申请入口 + 截止时间 + 门槛**（`kind='chance'`，`urgency` 与待办同一套取值）。
3. **三、有用信息（按来源与性质分四类）**：
   - **3.1 官方信息** —— 学校 / 书院 / 院系 / 团委 / 学生会等**官方渠道**发布的：比赛、招募、通知、规则、时间节点、截止日期。写清**谁发的、什么时候、截止或生效时间**（**可依赖**）。
   - **3.2 同学与群里的经验** —— QQ 水群、同学私聊、学长学姐的**评价、口碑、避坑、经验**（如"某老师给分""某场地怎么用""补退选会秒没"）。**必须标注"听说 / 个例"**（**只是参考**，不得当官方口径）。
   - **3.3 资源与工具** —— 可直接使用的**网站、资料、工具、优惠、云盘**（带可操作链接 + 验证状态）。
   - **3.4 生活与办事** —— 吃住行、维修、就医、快递等**确实会影响他的**信息（按他的偏好：只提会影响他的）。
   > 某类当天没有内容就**不写该类**，不要凑格式。
3. **「待确认 / 待核对」不是列表的一类**（2026-09-13 用户纠正："待确认不是让主 agent 确认的意思吗，你咋加到列表来了"）：
   它是**主 agent 自己**要跟的核对清单 → 写进它的手册 `docs\agent\WORKING.md` §十一（必要时在 `debug_<date>.md` 里跟着），
   **不进用户列表**。需要**他**拍板的事另有机制（「待确认价值」→ `ask_user_question`），两者别混。

> **为什么这样分**：官方信息可以依赖、同学评价只能参考——混在一起会让他误判；待办与信息混在一起则看不出"我到底要不要动手、先动哪件"。

> **分类是可演进的（用户 2026-09-12 授权）**：这套结构不是死规定——用户明确"**分类你以后也可以改，都是可以改的，按我的反馈/你的观察来**"。允许的调整：某类**长期为空 → 合并或删掉**；某类**内容变多 → 拆出子类**；发现**更好的切法 → 直接换**。**每次调整都记进下面的日志**（日期 + 改了什么 + 为什么），便于复盘。

- **2026-09-13 新增「二、机会与招募」（用户要求）**：原结构＝`一、待办` + `二、有用信息（2.1–2.4）`；
  用户在关卡里答「你可以创建一个新的大栏」→ 现结构＝`一、待办` + **`二、机会与招募（2.1–2.3，按距截止的时间分档）`** +

## 固定结构（六节，顺序不变）

### 0. 数据概览（表格）
消息总数、会话数、时间跨度、图片消息（本地命中 / 总数）、文章（已抓 / 总数）、文件数、系统消息数

### 1. 需要跟进的事项（未过期 / 有未来时限）
每条一块，字段固定：
- **【分类】标题**
  - 来源：会话显示名（id）· 发送者 · 时间
  - 事实：发生了什么（不拼接、不猜测）
  - 要做：动作 / 时间 / 地点 / 材料（缺项写"未知"）
  - 时限：…（**时间已过 → 不得放本节**，移入第 4 节）
  - 已知度：未知候选 / 已知 / 需与本人核对
  - 证据：消息 ts / 图片 md5 / 文章 url / 文件名

### 2. 状态变化与长期有效信息
身份、关系、计划、规则的变化与长期可用的结论；每条附来源与时间。

### 3. 媒体已读内容
- **3.1 图片**：逐条 `[会话 · 时间 · 发送者]` → 本地文件路径 · 图中**实际**内容 · 锚定方式（`content_md5` / `thumb_length`）+ `confidence` · 是否仅缩略图
- **3.2 文章**：标题 · 公众号 · 发布时间 · 正文要点（3–5 条）· 有无行动项 · 本地文件路径
- **3.3 文件**：原文件名 · 来源 · 内容要点 · 可读性问题（如有）

### 4. 已过时信息（仅存档，不再提醒）
一行一条：`[时间] 会话·发送者：一句话事实（已过期）`。**即时通知过期后只出现在这里，不得重复进第 1 节。**

### 5. 已知 / 已参与（不重复，只列名）
- 会话/事件名：一句说明（用户自己发的、自己问来的、亲历家常 → 归此节）

### 6. 未能解决 / 待核对
未下载媒体、抓取失败、上下文不足、字段缺失；每条给出定位信息与原因，**不编造**。

## 硬性纪律
1. 每条信息可追溯到具体消息（会话 + 时间）；不拼接、不猜测。
2. 图片必须用 `read_image` 实际读；文章必须用本机 Node 脚本抓正文；文件必须实际打开看。
   - **文章正文先查本地缓存** `output\window\articles\`（历史上抓过都在这里）→ 没有才联网抓；
     联网现在常被反爬拦到 captcha，抓不到就**如实标注**。当天清单见 `output\days\<date>_articles.md`（**有正文的必须读**）。
     *依据*：2026-09-13 算力券那条只读群消息、没读已缓存的正文，漏了线下联系人「<联系人> <电话>」。
3. 不确定 → 标"待核对"；缺失字段写"未知"，不编。
4. **时效判定**：作用＝"提醒当时去做某事"且时间已过 → 第 4 节；有未来时限或后续影响 → 第 1/2 节。
5. **去已知**：自己发的 / 自己问来的 / 亲历家常 → 第 5 节列名即可。
   - **粒度（2026-09-13 纠正）**：「已知」**按要点判、不按整条判**。他看过这条消息 ≠ 他知道里面的每个要点
     （联系人 / 找谁办 / 条件 / 额度 / 入口 / 技术口径）。正确处理＝**降级不丢弃**：已知部分压成一句背景，
     **未见的要点作为正文主体**；判据全文见 `guidelines.md` 原则 6 最后一条。
   - **同时别把"他自己经历过的过程"写进去**：他自己排查过的报错、自己问来的答复细节、别人（群友）的问题，
     都属"无用信息"——**只留他以后会用到的结论与入口**。*依据*：09-13 算力券条目把"500万→1000万 TPM 排查过程 /
     预冻结来龙去脉 / 容器实例≠镜像 / 试算用户权限"全写进去，被用户判为"无用信息太多、太长"。
6. **「待确认」只用于政策/口径级边界**（2–4 条）：**具体事实不许塞进去** ——
   联系人、有日期的活动、规则条款，**必须自己判断并提炼成条目**。判据见 `MAIN_AGENT_SPEC.md` §四第 4 步。
7. 时区统一 CST（UTC+8）；epoch 计算只用 Python 显式时区（**禁用 PowerShell `-UFormat %s`**，会 +8h）。
8. 媒体锚定优先级：内容 md5（conf 1.0）＞ 缩略图字节数 == `cdnthumblength`（conf 0.8）＞ 时间推定（必须标"推定"）。
9. **话题归并（2026-09-13 立，必做）**：**脚本只把材料摆到一屏**（`_timeline.md` 把全会话按时间合并、标出跨群同文），
   **"这是同一件事"必须由提炼者判断并合并成一条**。同一件事在不同会话/不同天出现时往往**换词**
   （实测：舞会 / 舞培 / 正装团购 是同一件事的三个面，散在 3 个会话里 → 一条都没报）。
   **但语义相近只能提示"去怀疑"，必须回原文核实才算合并** —— 反面教材：规范第一版把「尺码统计」也并进来，
   实际 09-12 原文是「学院会给每位同学**定制帽衫**」的尺码，**跟正装团购无关**；错例不仅教出错归并，
   还掩盖了"帽衫尺码没填"这条真待办。详见 `task_daily_template.md` §2ter 的反面教材。
   合并信号（任一命中即怀疑）：不同会话+时间挨得近 / 连续几天反复出现 / 同一链接·卡片·活动名·同一批人 /
   A 问的正是 B 在别处说的。**已有一条就改那一条，不要新开一条**；归并后仍"三问全否"的才不报。
   详见 `task_daily_template.md` §2ter。
10. **小卡片 ≠ 越长越好：裁剪清单（2026-09-13 用户："有些条目有点过于长了，不是说全是无用信息，但有些还是不用写的"）**。
    **该砍**（写进去只是搬运，不改变他做什么）：
    - **别人的人名 / 电话 / 联系方式** —— 只留**他会去找的那一个**（例：八院系联合活动里只留**秀钟**负责人，其余 7 个不写）；
    - **跟他无关的档位 / 套餐 / 明细** —— 例：他是男生，正装团购的**女装**档、皮鞋档、量体定制档、以及"西服 398+皮带 89+衬衫 110+领带 30"这种**分项拆价**全砍，只留**男装成品三档 + 起价**；
    - **售后 / 门店地址 / 商家承诺**（质保年限、保养门店、"同款同质同价"）；
    - **已经过去的事的过程**（"第一次舞培 9/12 已办完"一句带过，不展开）；
    - **原文式罗列**（八个院系名单、十几个奖项名额、十几条目录）；
    - **重复**：正文写过的，别在"为什么值得关注"里再说一遍。
    **该留**：一句话总结（≤40 字）· 这是什么 · **他要做的动作** · 期限 · 入口（链接/二维码/表）· **他会找的那个人** · 为什么值得他花时间。
    **他短句反馈里说"保留 X" / "只保留 X 信息" / "只留 X"的读法（2026-09-14 立）**：**＝把这一条聚焦到 X、其余全部砍掉**（**不是**"整条不动"，也不是"顺手留点别的"）。
    实测两条：① 清理关卡他答「cjl 保留参考书，其他所有删了」，被我读成"整条保留"；次日他明确「我的意思是**只留下参考书的有用信息，其他精简掉**」→ 该条 757 字收到 **263 字**；
    ② 他引用算力券那条说「**只保留联系方式信息**」→ 685 字收到 **208 字**（只留"群里问工程师 / 华业大厦 1103 <联系人> <电话> / 7×24 支持"，额度、入口、专项申请、计费规则全砍）。
    **凡不确定他指哪一部分，就按"体积更小、只留他点名的那部分"处理**。
    **够用线**：单条正文超过 **~1000 字**就停下来问一句"这 XX 字里有哪几段是他真会用到的"；超出的部分按上面的清单砍
    （实测靶子：舞会那条 1697 字、人工智能青年大会那条 1176 字，都该收）。

   3c. **文件检查与价值判断（原则 16，每日必做）**：把本次涉及的文件都过一遍（能读就读：PDF/Office 提取正文、图片读图、音视频标注），判断**有用 / 无用无价值**，把**无用清单**（名称/大小/来源/理由）写进「文件处置建议」供用户确认删除；**严禁自行删除**；拿不到的标注"本地无、需客户端下载"。
   3d. **有用图片嵌入报告 + 文件给可点击链接**：承载信息的图（截图/通知/书单/二维码）用 ``<img src="../output/window/images/<会话>/<文件>.jpg" width="480" alt="说明">`` 嵌入；文件类资源给路径链接（工作区内用相对路径；工作区外用 `file:///` + 可复制完整路径；本机没有的写"需客户端下载"）。表情包/梗图不嵌。
4. **资源型信息的链接深挖（原则 13，必含）**：
   - 凡"可领取 / 可报名 / 可下载 / 可使用"的信息，**必须给出可操作链接**；

### 硬性纪律 12：动作项永不因「他已经知道」而删 + 作业/截止必须留台账（2026-09-15，用户纠正）

**起因（实测事故）**：09-14 那一轮，崔老师在课程通知群 12:45 发的「**今天作业：课本第 10 页，3，4，8**」
**在语料里明明有**（`slice01` 里连同 12:47「作业怎样提交」、12:56「那我们也要今天做那个作业吗」、
13:01「针对课序号 11 的班级学生」、14:28 重发，一共 5 行），
却**被提炼层当成"日常 / 他可能已经知道"漏掉了** → 用户原话：
「**这种重要的待办就算我看过也应该列进列表里啊**」。

**规则（两条，都是硬性的）**：

1. **「已知」不是删除动作项的理由。** 凡是**要他本人做一次动作**的（作业、交材料、报名、截止、回复、去现场），
   只要三问第 ① 问成立（需要他做什么＝是）→ **一律进待办**：哪怕他当天就在群里、哪怕他可能已经看到、哪怕只有一行。
   **「已知」过滤器只作用于信息类（3.x）；对动作类是无效否决。**
   → 判据一句话：**"这条要他做事吗？"是的话，不许拿"他知道"当理由删。**
2. **作业 / 截止必须留台账（可核查）。** 提炼时对当天语料做一次机械扫描 ——
   **本机没有 `rg`**，用等价工具（词表已含动作项与机会项两节）：
   ```
   python tools\hw_ledger_scan.py <date>
   → output\days\<date>_action_scan.md（动作 N 条 / 机会 M 条，逐行列出）
   ```
   （旧口径 `rg -N "作业|截止|提交|上交|ddl|DDL|报名|小测|考试|第\d+页"` 的词表**不完整**，
   见下面**硬性纪律 13**：它漏掉了"问卷/招募/征集"这一类。）
   **每一条命中行都要有处置记录**（进了哪条 / 为什么不进），写进交付稿的 debug 日志或 `_hw_ledger.md`。

### 硬性纪律 13：**一条消息里有几件事，就要有几条处置；"问卷/招募/征集"必须扫（2026-09-15 晚，用户报漏）**

**起因（实测漏报）**：09-13 22:30 张一凡在【2026 AI创新大赛】新生选手2群发的同一条 @所有人 消息里同时有
① 入围决赛名单 ② 后续安排（广场上架/养成计划）③ 报销口径 ④ **反馈问卷** ⑤ **招募问卷**
（"如果有希望参与清小搭团队、清华人工智能生态建设、ai赛事筹办的同学，可以填写报名"）。
那一轮**报了 ① ②**（就是现在面板上的 AI 大赛决赛条目，连"养成计划"都写了），**④ ⑤ 一条没报**
——用户直接问「**这个招募问卷不应该是重要信息吗？为什么没有识别到**」。
**与 09-14 漏崔老师作业同型**：不是取数漏的（`2026-09-13.jsonl` 第 5677 行就是它、增量信号文件里也有），
是**提炼层"一条消息只报一件事"**。

**真实的漏报链路（2026-09-15 晚查明，三层都由同一个毛病造成：静默截断，且不报错）**：
① 语料视图加载 **300 字** → ② `units_day` 收到 **260 字** → ③ `split_day.load` 再砍到 **240 字**；
那条 525 字的公告**尾部**（报销／反馈问卷／招募问卷）**从头到尾没进过任何视图**，所以任何读它的人都不可能看见。
叠加 ④ **台账词表没有「问卷/招募/征集」** → 连"这里有东西被漏了"这个信号都没有。
**修法（已落地）**：`split_day.load` 不再截断；视图统一「**头 400 + 尾 400 + 显式省略标注**」（长消息的入口与链接通常在末尾）；
`hw_ledger_scan.py` 拆出**【机会】一节**；09-12/09-13/09-14 语料已重切、`COVERAGE OK`。
→ **教训一句话：截断必须"显式标注 + 保尾"，且任何静默截断都等于漏报**（本文件顶部那条换行/字符口径同理）。

**规则（两条硬性）**：

1. **一条消息里的多个"动作/机会"必须逐条处置**，不许因为已经报了其中一件就跳过其余。
   凡是消息里出现**独立的动作或入口**（问卷 / 报名表 / 招募 / 征集 / 上传链接 / 登记表 / 接龙），
   每一个都要么进主稿、要么在台账里写明为什么不进。
2. **机会型词表必须与动作项一起扫**（`问卷|招募|征集|志愿者|选拔|观众|接龙|收集表|报名表|自主报名|填写|调研`）：
   判据仍是三问，但**"这是别人的招募"不是不进的理由** —— 只要**他可以报名/可以被选拔/可以参与**，
   就是**机会**（`kind='chance'`，进「二、机会与招募」）；**带截止时间且要他本人交一次动作的**，进待办。
   例：AI 大赛招募问卷 → 机会（可参与清小搭团队 / AI 生态建设 / 赛事筹办）；
   "首都产业一线科技人才走进高校"观众招募（9/15 24:00 前报名、9/17 宣讲）→ 待办（有硬截止）。
   **禁止静默丢弃；没有台账＝这一轮不算交付完成**（主 agent 验收时对着这份台账抽查语料）。

**为什么**：动作项漏一条的代价（漏交作业、错过截止）远大于多留一条；而"他看过的群里消息"里，
恰好最容易藏着**他看到了但没记住、没当回事**的待办。
