**一句话：把"读"全部挪到本机（0 元），云端只留"写"（一次调用 + 主 agent 收尾）。**

### 子代理还要不要派？（2026-09-17 用户问「现在不用再派子代理了？」）

**常规轮：0–1 个**（从旧流程的 4–6 个降下来）。原来子代理干的活现在各有接手：

| 原来谁干 | 干的活 | 现在谁干 |
|---|---|---|
| 4–5 个云端子代理 | **逐片读 600 行**、逐条读、产出候选 | **本地 qwen3.5:9b**（阶段 2；¥0） |
| 图片线子代理 | 回看那几十张图 | **本地 9B 细读遍**（阶段 4；¥0） |
| 跨会话子代理 | 跨群/跨天归并 | **脚本索引**（timeline 的跨群同文 A/B、threads）＋ **阶段 5 一次调用** |

**仍然可能派的三种情况**（别理解成"永远不派"）：
1. **阶段 5 可选派 1 个**：想让"归并/成稿"走 **THU 免费**时，派一个**钉到 THU 的前台子代理**做这一次调用（主 agent 本体在 paratera）；不派也行（主 agent 自己一次调用 ≈¥0.05）。
2. **兜底**：本地模型不可用 / 一次要补好几天漏 ⇒ **回到老路**（4–5 个云端子代理逐片读；贵但不断线）。
3. **上下文隔离**：单块材料特别大、不想装进主 agent 上下文时，丢给 1 个子代理核 —— 这时它是**隔离手段**，不是省 token 手段。

**两条不许走偏**：① **"不派子代理"≠"没人逐条读"** —— 全覆盖纪律没降，执行者换成本机进程，同样是"一块一块读、块间不共享上下文"；
② **分工没变** —— 主 agent 仍是编排者（跑脚本、归并、验收、回写面板），它只是不再为"读"去派一群云端 agent。

## 1. 新流程（逐步）

### 阶段 0 · 触发与前置 — 主 agent，3–5 步（≈¥0.15）
- **路由＝两个常驻会话，按需切换（2026-09-17 用户定案）**：`sessThu`（provider `deepseek`，免费、窗口 **200k**、不能读图）
  与 `sessParatera`（`paratera`，付费、窗口 **1M**、能读图）。**宿主在唤醒主 agent 之前**就用插件侧可达性探测（`fetch`）选好会话
  （`routePick`），所以**不花主 agent 的步数**、也不需要用户做任何事。**THU 的上下文刷新阈值以 `/state` 的
  `ctxRatioThu` 实时值为准**（代码默认 0.7，`loadState` 把盘上旧值夹到 ≤0.75；**不要在这里写死数字** ——
  历史上这里写过 0.9，而 0.9 > DSH 自己的压缩线 0.8 ⇒ 那个参数是死的，见 `KNOWN_ISSUES` B35）。
  **手动触发＝"选提供商"（2026-09-17 白天定稿）**：侧栏「获取」是**下拉**（<免费线>/ <付费线>）—— 他点哪个，
  宿主就 `POST /collect {route}` **现场探哪条**：通了才 `triggerRound`；不通只回失败（按钮闪红底白字「获取失败」2.6 秒后恢复，
  **采集指针一动不动**）。**你被唤醒就说明那条线路当时是通的**，提示词开头会写明本轮模式。
  **自动那条路**仍看 `gwPolicy`：`skip`（默认，不通则不跑、0 元）/ `pipeline`（只跑管线阶段，约 ¥0.3–0.7）/ `full`（照常全轮，约 ¥1–2）。
  **不弹任何卡片**（用户 2026-09-17 否掉了 `ask_user_question` 这条路：卡片只出现在"提问那条会话"的输入框里、他多半看不到，而且"问"本身要先唤醒付费会话）。
  手动切会话：`POST /chat-feed/api/route-pick {"route":"thu"|"paratera"}`；细判：`tools\route_probe.py`（带凭据 + 看两个槽）。
  **不要 /rotate 换线路；也不要用会话内 selectModel 改指向**（那条已实测可用但降级为备用：同一个会话切到 200k 会溢出）。
- 读 `/state?slim=1`：看 `lastCollectAt`、`collectDay`、是否断档；缺哪天补哪天。
- `tools\wx_status.py` 确认微信登录态（未登录 → 报「待微信登录」，不报失败）。
- **成本依据**：主 agent 每步 ≈ ¥0.035（见 §2 的单步公式）。

### 阶段 1 · 取数 — **脚本**，`scripts\daily_prep.py <date>`（21 步）
- 解密微信/QQ → 当天消息 → 简报 → 文章 → 时间轴 → 单元化 → **3i 本地小模型过筛** → 图片索引 → **3j 本地视觉** → 链接验证 → 容量扫描。
- **成本：0 元**（3i 与 3j 都是本机 Ollama，零 API 花费）。
- 产出：`output\days\<date>_*`（含 `_units.md`、`_units_filtered.md`、`_timeline.md`、`_vision.md`、`_units_dropped.md`）。

### 阶段 2 · 读 + 初提 — **本地模型**，`tools\local_prepass.py <date>`（★新增）

> **用哪个本地模型（2026-09-17 用户已定）**：默认 **`qwen3.6:35b-a3b`（A3B）**，`qwen3.5:9b` 用 `--model qwen3.5:9b` 作快速预演。
> 依据：09-16 全天 19 块 **A3B 255 秒 / 73 条 / 0 跑飞** vs **9B 337 秒 / 84 条 / 1 块跑飞**（9B 会输出 2.5 万 token 后归零、
> **静默丢掉一整块**）；一天绝对时间只差 1–2 分钟、两者都 0 元 ⇒ 取"少丢东西"。对照见 `docs\A3B-VS-9B.md`。
- 把语料切 **150–200 行/块**（块之间**不共享上下文**）→ 逐块问："挑出对冯思韬有用的条目（三问），输出 JSON"。
- **成本：0 元**
- **实测依据**（2026-09-17，09-14 全天 2,467 行）：
  - **111 秒**（17 块，平均 6.6 s/块）
  - 人工逐条核对 **覆盖 DSH 基线 13/14 = 93%**（9 条完整 + 4 条半 + 1 条漏）
  - 短板：**约 15% 噪音**（会把群里碎对话当条目）、对"反诈/平台入口"类不敏感
- 产出：`output\days\<date>_candidates.json`
- **硬要求：每条候选必须带来源锚点**（`群名 + HH:MM + 分片文件名 + 行号`）。
  理由（2026-09-17 实测）：**本地模型会编造细节** —— 原文是「【禁水】秀钟6字班通知群：2026-2027学年秋季学期SRT立项通知…」，而它写成「**经管学院** SRT 立项通知」，**"经管学院"是它加的**。
  带了锚点，阶段 5 就能**一条 grep 回原文核**：既治编造，也补"半覆盖"缺掉的细节（金额/截止/联系人）。

### 阶段 3 · 机械台账 — **脚本**，`tools\hw_ledger_scan.py <date>`
- 动作词（作业/截止/提交/报名/小测/考试/…）与机会词（问卷/招募/征集/志愿者/选拔/观众/…）两节扫描。
- **成本：0 元**；作用：**与阶段 2 取并集兜漏**（本地不敏感的类型由词表兜住）。

### 阶段 4 · 图片线 — **本地 qwen3.5:9b**（升级 3j：加"细读遍"）
- 第一遍（现状）：每张图粗判 `{what, action, fields, noise, why}` → 写进 `_vision.md`。
- 第二遍（★新增）：只对"**需回看**"的那几十张跑**细读提示词**（用 `_h.jpg` 高清版），把金额/截止/联系人等**细节**也写进 `_vision.md`。
- **成本：0 元**
- **实测依据**：09-16 共 127 张 / **84 秒** / 均 0.7 s/张；单张真图细读实测 **0.9 秒**，输出结构化且准确
  （例：`{"what":"清华环境学院教授温宗国的详细履历表格","fields":["姓名","职称","院系","联系方式","官网","研究方向"]}`）。
- ⇒ 之后**子代理不必再看图**（看图这步的云端成本归零）。

### 阶段 5 · 归并 + 三问筛选 + 成稿 — **一次调用**（不并行）
- 输入：阶段 2 的候选（几十条、**几 KB**）＋阶段 3 台账 ＋阶段 4 图片细节 ＋ `_timeline.md` 的**索引头**（跨群同文 A/B）＋ `_threads.md`。
- 输出：`output\daily\<date>\items.json`（正式条目：一句话总结 + 小卡片正文，含入口/联系人/条件/期限/口径差异）。
- 通道：**THU 免费**（跑一次 HTTP 调用，失败重试 3 次 → 回退 paratera）；**一次调用、天然不需要并行**，正好绕开 THU 的两个短板。
- **成本依据**：输入 ≈8k token（未命中 8k × ¥2/M = ¥0.016）＋输出 ≈4k（4k × ¥8/M = ¥0.032）⇒ **≈ ¥0.05**；THU ＝ **0 元**。

### 阶段 6 · 验收 + 回写 + 收尾 — 主 agent，30–80 步（≈¥1–3）
- 三问复核；**动作项逐条对台账**；清理（过期 + 已勾选，先 `ask_user_question` 征求同意）；
- `/state?slim=1` 对账 → `POST /items-patch`（只发改动的几条，不必整表）→ `export_list_mirror.py` + `export_day_items.py`；
- 知识库回写 + `mnemon_remember` 双写 + `mem_audit` 自证 + `debug_<date>.md`；
- **拨采集指针（仅当本轮不是宿主触发时）**：`POST /chat-feed/api/collect {"at":<本轮结束毫秒>,"confirm":"skip-window"}` ——
  插件**只在它自己触发的那一轮**拨指针（`fireRound`），人工叫起来的轮不被记账 ⇒ 不拨的话下一轮 `since` 落后
  （实测：产物末条 2026-09-17 01:41:57，`lastCollectAt` 却停在 2026-09-15 21:44；2026-09-17 白天已拨正）。详见 `docs\KNOWN_ISSUES.md` B30。
- **这里是新流程里唯一的大头**（见 §2）。

## 2. 费用估算

### 2.1 单步公式（实测锚定）

```
每步 ≈ 缓存读 × ¥0.04/M + 每步新增输入 × ¥2/M + 输出 × ¥8/M
     ≈ 200k × 0.04/M + 10k × 2/M + 1k × 8/M
     ≈ ¥0.008 + ¥0.020 + ¥0.008 = **≈ ¥0.035/步**
```
（与 09-14 实测吻合：836 步子代理 ≈ ¥30；一个 420 步子代理 ≈ ¥15。）

### 2.2 每阶段

| 阶段 | 谁 | 步数/调用 | 费用 |
|---|---|---|---|
| 0 触发前置 | 主 agent | 3–5 步 | ¥0.10–0.18 |
| 1 取数 | 脚本 + 本地模型 | — | **¥0** |
| 2 读+初提 | 本地 9B | 17 次本地调用 | **¥0** |
| 3 机械台账 | 脚本 | — | **¥0** |
| 4 图片粗判+细读 | 本地 9B | 127 + ~73 次本地调用 | **¥0** |
| 5 归并成稿 | 一次调用 | 1 次 | **¥0**（THU）／¥0.05（paratera） |
| 6 验收回写收尾 | 主 agent | 30–80 步 | **¥1.1–2.8** |
| **合计** | | | **≈ ¥1.2–3.0** |

### 2.3 三种配置下的每轮花费

| 配置 | 每轮 | 说明 |
|---|---|---|

## 3. 风险与回退（每一步都有退路）

| 风险 | 回退 |

| 整体质量下降 | **双轨对比**（同一份数据：本地首遍 vs 全云端），不比就退回老路 |

## 5. 验收指标与测量方法

| 指标 | 目标 | 怎么测 |
|---|---|---|
| 每轮真实花费 | ≤ ¥3 | `node docs\tools\line_daily_cost.mjs --cwd=agent,chat-feed` |
| 本地初提覆盖率 | ≥ 90% | `tools\prepass_audit.py <date>`（对基线）+ 人工抽检 |
| 噪音率 | ≤ 20%（由阶段 5 滤掉） | 同上 |
| 图片线云端成本 | = 0 | `line_daily_cost.mjs` 里图片相关步骤应为本地（0 元） |
| 漏报 | 动作项台账**每条命中都有处置** | `hw_ledger_scan.py` 两节逐条对账 |
| 主 agent 步数 | ≤ 80 步/轮 | `/state` + 会话事件 |

> **2026-09-17 补**：成本工具已改成**按 provider 计价** —— 清华免费网关（provider `deepseek`）的 token 进「免费token」列、**不进账单**；
equest/header/
equest/context 决定归属。另外提醒一个**不受主 agent 路由影响的付费点**：`mnemon` 记忆插件的 `taskAgentModel` 在 `~/.dsh/settings.yaml` 里固定为 `paratera/<付费模型>` —— 每次记忆归档/召回判定都会起一个 paratera 子会话（实测 2026-09-17：那天这条线 ¥0.83 里约 ¥0.8 是它）。
